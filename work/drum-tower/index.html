01 / OVERVIEW

让柱网、层级与构件沿着同一套规则生成。

项目以广西三江侗族鼓楼为研究对象。与复刻一座固定鼓楼不同，我尝试从其平面组织、柱网关系、层檐数量、竖向高度、逐层收分、构件尺度与顶部结构中提取可计算的关系，并在 Rhino + Grasshopper 中建立联动参数系统。模型能够通过改变多个控制变量重新生成柱网、层级骨架与构架实体，用于观察传统建筑形态如何由一套相互依赖的规则产生。

03 / PARAMETRIC SYSTEM

从柱网规则到鼓楼构架。

先定义平面、层级和构件参数，再逐步生成柱网、梁枋和整体构架。下面展示 Grasshopper 控制面板、生成步骤和不同平面配置。

01 / RULE EXTRACTION

提取平面、层级与构件参数

鼓楼并不是由孤立尺寸组成，而是由平面、柱网、层级、比例与构件 之间的相互关系共同决定。参数化转译首先需要把这些隐性关系拆解成 可以被 Grasshopper 读取和修改的变量。

01

Plan geometry

平面与柱网
  • Plan sides / 平面边数
  • Base radius / 底层控制半径
  • Column spacing / 柱网间距
  • Inner column distance / 内柱距离
02

Vertical hierarchy

竖向层级
  • Total height / 总体高度
  • Number of eaves / 层檐数量
  • Floor elevation / 层间标高
  • Top structure height / 顶部高度
03

Proportion

比例与收分
  • Layer scaling / 逐层缩放
  • Taper ratio / 收分比例
  • Eave projection / 屋檐出挑
  • Section relationship / 截面关系
04

Members

构件尺度
  • Primary columns / 主柱
  • Secondary columns / 次柱
  • Horizontal members / 横向梁枋
  • Radial members / 向心构件
02 / PARAMETRIC CONTROL

在 Grasshopper 中设置联动参数

参数并不是独立滑块。平面边数、层数、高度与收分关系会同时影响 后续节点、线框和构件几何，因此整个模型被组织成一条具有数据依赖 关系的生成链。

04 / STRUCTURAL GENERATION

分步查看柱体与梁枋

生成过程被拆分为多个可检查的结构阶段，使模型不仅输出最终外形， 也能观察鼓楼从柱网、梁枋到完整空间构架逐步形成的过程。

01

Primary columns

主要支撑柱

从底层平面和柱网关系开始，生成承担主要竖向关系的柱体体系。

02

Horizontal framework

横向构架

依据每层标高建立环向梁枋，使不同柱体在水平方向形成连续结构关系。

03

Vertical framework

竖向构架

连接不同层级的关键节点，将逐层缩放后的平面关系组织为整体竖向骨架。

05 / DESIGN VARIATIONS

比较四角与八角配置

平面边数作为全局输入之一，可以改变底层多边形与柱网组织，同时 保留后续层级、缩放和构件生成逻辑。四角与八角模型因此成为同一 参数系统下的不同输出，而不是两个独立模型。

06 / STRUCTURAL EXPRESSION

用爆炸图检查构架层级

爆炸表达进一步分离不同层级，使参数系统中的垂直序列、 重复构架与整体塔式形态能够同时被阅读。

05 / OUTCOME & DOCUMENTATION

从参数构架到材质表达。

  1. 01建立由平面、柱网、层级、收分、构件与顶部结构共同组成的 Grasshopper 参数控制系统。
  2. 02完成从底层柱网、层级骨架到柱梁构架实体化的连续生成流程。
  3. 03使用同一套生成逻辑输出四角、八角等不同平面条件下的鼓楼模型。
  4. 04通过 Rhino 模型渲染与 AI 辅助材质表达，对结构逻辑与最终建筑形态进行不同层级的可视化。
06 / REFLECTION & NEXT STEPS

榫卯细节与地方尺寸尚待校准。

当前模型主要表达鼓楼的整体形态、柱网、层檐关系和主要构架逻辑，并不能等同于真实施工模型。榫卯节点、斗拱细部、屋面瓦作以及不同地区鼓楼的具体尺寸差异仍未被完整建模。现阶段参数范围主要来自文献整理、建筑特征归纳与模型推演，后续需要结合更多实测案例校准参数，并进一步研究构件级营造规则。
